# 원본 폴더 관리 계획: 설정 화면에서 폴더 보기·추가·빼기 (Phase 9)

_2026-11-01 사용자 요청·결정 4개 확정(2절) · 미결 5개도 같은 날 사용자 결정(2절 아래 표, 8절)_

## 1. 목표

일반인이 터미널 명령 없이 설정 화면(`gate ui`)에서 게이트에 연결된 원본 폴더를 보고, 폴더를 더 연결하고, 연결을 뺄 수 있게 한다. 폴더를 연결하면 그 폴더는 **게이트로만** 읽힌다. 에이전트 작업 폴더 설정에서 직접 읽기를 함께 막는다.

사용자 요청(2026-11-01): "ui에서 마운트도 ui에서 진행하게 해 줄 수 있어? 현재 마운트한 폴더도 나오게, 추가도 할 수 있게."

## 2. 확정한 결정 (사용자, 2026-11-01)

| 항목 | 결정 | 이유·비고 |
|---|---|---|
| 폴더 고르기 | **맥 폴더 선택 창**(Finder). 화면의 [폴더 추가]를 누르면 화면 서버가 `osascript`로 띄운다 | 일반인은 경로를 모른다. 승인 창처럼 이 컴퓨터에서만 뜬다. 경로 직접 입력은 화면에 두지 않는다(터미널 `gate mount add`는 둔다, 4.4) |

## 3. 지금 구조와 바꿔야 하는 곳

- 데몬은 원본 폴더 하나를 띄울 때 받는다(`gate serve --source`, `gate/cli.py` `_serve` → `PlainStore(source)`, `gate/store.py`). 띄운 뒤에는 바꿀 수 없다. 원본 밖을 가리키는 심볼릭 링크는 따라가지 않는다(`resolve`).
- 보호 설정은 원본 폴더 하나를 적는다(`gate/workspace.py` `GatePaths.protected()` → `protection_settings`·`agent_settings`). `gate setup`(`gate/claude_setup.py`)도 같은 함수를 쓴다.
- 설정 화면은 원본 폴더를 모른다(`gate/ui.py`, `gate/ui_api.py` `UiApp`, `gate/ui_static/`).
- 경로 규칙·폴더 승인·감사 기록은 게이트 안 경로(`/상담/…`)로 동작한다(`gate/policy.py` `match_path`: `/`가 없는 패턴은 어느 깊이에서나 맞음). 그래서 추가 폴더를 `/이름/` 아래에 보여 주면 기본 거부 규칙(`*.env`, `*.pem` 등)과 사용자 규칙이 그대로 걸린다.

폴더를 추가할 때 세 곳을 함께 바꾼다. **하나라도 빠지면 구멍이다.** 게이트만 바꾸고 보호 설정을 빼먹으면, 에이전트가 게이트를 거치지 않고 원본을 바로 읽을 수 있다.

1. **게이트**: 폴더 목록 파일을 읽어 여러 폴더를 한 이름 공간에 보여 준다(4.1·4.2).
2. **보호 설정**: 추가한 폴더를 작업 폴더 설정의 거부 목록에 넣는다(4.3).
3. **화면**: 목록·추가·빼기(5절).

## 4. 설계

### 4.1 이름 공간 (미결 1의 추천안 A 기준)

- `--source` 폴더(이하 **기본 폴더**)는 지금처럼 `/`에 둔다. 추가한 폴더는 `/` 바로 아래 가상 폴더 `/<이름>/`로 보인다.
  - 예: 기본 폴더에 `상담/`·`안내문.txt`가 있고 `~/Documents/가계부`를 추가하면, `gate ls /`는 `가계부/  상담/  안내문.txt`를 보여 준다.
- 기존 경로·정책 경로 규칙·감사 기록·폴더 승인·판단 캐시가 그대로 맞는다. 기본 폴더는 화면에서 뺄 수 없다("기본 · 띄울 때 정함"으로 표시).
- 이름은 폴더 이름을 그대로 쓴다. 기본 폴더의 맨 위 항목이나 다른 추가 폴더와 겹치면 뒤에 ` 2`, ` 3`을 붙인다(미결 4). `/`와 제어 문자는 쓸 수 없다. 이름은 NFC로 맞춘다(경로 규칙과 같음).
- 기본 폴더에 나중에 같은 이름이 생기면 추가 폴더가 이긴다. 기본 폴더 쪽 항목은 가려지고, 데몬은 시작할 때와 목록 파일이 바뀔 때 경고를 한 줄 남긴다.

### 4.2 폴더 목록 파일과 데몬

- 파일: `mounts.yaml`. 위치는 **정책 파일과 같은 폴더**(`gate-data/mounts.yaml`)로 고정한다. 0600으로 쓰고, 심볼릭 링크로 바꿔치기한 경로에는 쓰지 않는다(정책 파일과 같은 쓰기 방식).
  - 구현 때 바꿈(2026-11-01): 처음 안의 `--mounts`·`GATE_MOUNTS`는 두지 않는다. 데몬·화면·작업 폴더 설정이 서로 다른 목록 파일을 보면, 화면이 막은 목록과 게이트가 보여 주는 목록이 어긋나고 보호하지 않은 목록 파일이 생긴다. 정책 파일 경로 하나로 셋이 같은 파일을 찾는다.
  - 정책 파일 없이 띄운 데몬(`gate serve`에 `--policy`·`GATE_POLICY` 없음)은 추가 폴더를 쓰지 않는다(기본 폴더만).
  ```yaml
  version: 1
  mounts:
    - name: 가계부
      path: /Users/me/Documents/가계부      # 실제 경로(심볼릭 링크를 따라간 것)
      added_at: 2026-11-02T10:00:00+09:00
      added_by: ui                          # ui | terminal
      connected: true                       # false면 게이트에서 뺐고 직접 읽기 막기만 남음(미결 2 A)
  ```
- 데몬은 요청마다 목록 파일이 바뀌었는지 본다(정책 파일 `PolicySource`와 같은 방식). 그래서 데몬을 다시 띄우지 않아도 된다.
  - 파일이 깨졌으면 정책 파일이 깨졌을 때처럼 **내용 읽기를 모두 막는다.** 목록·`stat`은 기본 폴더만 보여 준다. 화면에 배너를 띄운다.
  - 데몬도 목록을 읽을 때 4.5 검사를 다시 한다(목록 파일은 화면을 거치지 않고도 바뀔 수 있다). 걸리는 항목은 보여 주지 않고 stderr에 경고한다. 예: 누가 목록에 감사 로그 폴더를 적어도 게이트가 `audit.key`를 내주지 않는다.
  - 추가 폴더가 사라졌으면(외장 디스크 뺌, 폴더 지움) 그 이름은 `gate ls /`에 나오지 않는다. 읽으면 `ENOENT`다. 화면에는 "찾을 수 없음"으로 보인다.
- 저장소: `PlainStore`를 감싸는 `MountedStore`(가칭). 첫 칸이 추가 폴더 이름이면 그 폴더의 `PlainStore`로, 아니면 기본 폴더로 보낸다. `/` 목록은 둘을 합친다. 심볼릭 링크는 각 폴더 안에서만 따라간다(폴더 사이를 넘지 않음).
- 감사 기록은 지금처럼 게이트 안 경로를 남긴다. 실제 경로는 남기지 않는다.

### 4.3 보호 설정 다시 쓰기

- `GatePaths.protected()`에 추가 폴더 전부와 `mounts.yaml`을 넣는다. `mounts.yaml`은 정책 파일처럼 `Read`·`Edit` 거부와 샌드박스 `denyRead`로 막는다. 에이전트가 목록을 바꿔 다른 폴더를 열게 하지 못하게 하려는 것이다.
- **작업 폴더 등록**: `gate workspace init`이 만든 작업 폴더를 등록 파일(`gate-data/workspaces.yaml`, 0600, 보호 대상)에 적는다. 폴더를 추가하거나 빼면 등록된 작업 폴더마다 `.claude/settings.json`을 지금 목록으로 다시 쓴다(미결 5). 이미 있는 `gate-data/agent-workspace`는 등록 기록이 없으므로 한 번 `gate workspace init --force`로 다시 만든다.
- **순서**
  - 추가: ① 작업 폴더 설정 다시 쓰기(막기) → ② `mounts.yaml`에 적기(게이트에 열기). ①이 하나라도 실패하면 ②를 하지 않는다.
  - 빼기: `mounts.yaml`에서 `connected: false`로 바꾼다. 작업 폴더 설정은 그대로다(보호 남김, 미결 2 A).
  - 보호도 풀기: ① `mounts.yaml`에서 항목을 지운다 → ② 작업 폴더 설정을 다시 쓴다. 느슨해지는 바꿈이라 한 번 더 확인받는다.
  - 등록 파일 `workspaces.yaml`에는 작업 폴더마다 설정을 만들 때 쓴 경로(원본·소켓·정책·감사 로그·`gate` 실행 파일)와 마지막으로 쓴 설정 파일의 SHA-256을 적는다. 다시 쓸 때 이 경로로 설정을 만들고, 지금 파일의 해시가 기록과 다르면 손으로 바뀐 것으로 본다.
  - 화면과 `gate mount list`의 기본 폴더는 등록된 작업 폴더의 원본 경로다(데몬은 띄울 때 받은 `--source`를 쓴다). 등록된 작업 폴더가 없으면 기본 폴더 줄은 "알 수 없음"이고, 추가할 때 "보호할 작업 폴더가 없어요"라고 알린다.
- 작업 폴더 설정이 손으로 바뀌어 있으면(지금 만들 내용과 다르고, 마지막으로 쓴 내용과도 다르면) 자동으로 덮지 않는다. 그때는 추가도 하지 않고 "작업 폴더 설정이 손으로 바뀌어 있어요. `gate workspace init --force`로 다시 만든 뒤 추가하세요"라고 알린다.
- **전역 설치**(`gate setup`): 설치 기록(`gate/claude_setup.py` `record_path`)이 있으면 화면과 CLI가 "전역 설정에는 아직 반영되지 않았어요. 터미널에서 `gate setup`을 다시 실행하세요"라고 알린다. `gate setup`은 `mounts.yaml`도 읽어 모든 폴더를 막는다.
- **이미 켜진 에이전트 세션**: Claude Code가 세션 중에 바뀐 설정(특히 샌드박스 `denyRead`)을 바로 반영하는지는 모른다. 하네스로 잰 뒤(7절 W20) 반영되지 않으면, 추가를 마칠 때 "에이전트 세션을 다시 시작해야 이 폴더 직접 열기가 막혀요"라고 알린다(미결 3).
  - 참고: 추가하기 **전**에도 그 폴더는 에이전트가 직접 읽을 수 있다. 샌드박스는 `denyRead`에 적은 곳만 막는다. 연결은 보호를 더하는 일이기도 하다.

### 4.4 터미널 명령 `gate mount`

화면과 같은 코드(`gate/mount_change.py`, 가칭. `policy_change.py`처럼 계산·쓰기를 맡고 CLI·화면은 묻기·출력만)를 쓴다.

```bash
gate mount list                      # 이름, 게이트 안 경로, 실제 경로, 상태(있음·찾을 수 없음), 작업 폴더 반영 여부
gate mount add ~/Documents/가계부      # 확인 뒤 연결 (사람 터미널에서만)
gate mount remove 가계부              # 확인 뒤 빼기 (사람 터미널에서만). 직접 읽기 막기는 남는다
gate mount unprotect 가계부           # 보호도 풀기 (느슨해짐, 한 번 더 확인)
```

- 바꾸는 명령은 `gate policy`처럼 실제 터미널에서만 받는다(입력이 터미널이 아니면 거부).
- 추가는 에이전트에게 더 많이 보여 주는 바꿈이라, 느슨해지는 정책 바꿈처럼 한 번 더 묻는다.

### 4.5 추가할 수 없는 폴더

다음과 겹치면(같음·안에 있음·감쌈) 거부한다. 이유를 한 줄로 알린다.

- `/`, 시스템 폴더. `/System`, `/Library`, `/usr`, `/bin`, `/sbin`, `/etc`, `/private/etc`, `/Applications`는 그 안도 거부한다. `/private`, `/Volumes`, `/Users`는 그 폴더 자체와 감싸는 폴더만 거부한다(`/Volumes/외장`, `/private/tmp/…`는 된다)
- 등록된 작업 폴더. 홈 폴더 전체처럼 작업 폴더를 감싸는 폴더도 여기에 걸린다. 감싸는 폴더를 막으면 에이전트가 자기 작업 폴더를 못 읽는다.
- 게이트 데이터(정책·정책 기록·감사 로그·소켓 폴더·`mounts.yaml`·`workspaces.yaml`)
- `gate` 실행 파일이 있는 폴더(저장소·`.venv`). 막으면 에이전트가 `gate`를 실행하지 못한다.
- `~/.claude`, `~/.claude.json`
- 기본 폴더와 이미 추가한 폴더(겹치는 연결 금지)
- 개수는 최대 20개로 둔다(보호 설정이 너무 길어지지 않게).

## 5. 화면

설정 화면에 **"원본 폴더"** 절을 연결 상태 카드 아래에 둔다(디자인은 Phase 8 기준을 따른다: 숲색, 각진 모서리, 설계선, 상태 태그 22px).

- **목록**(줄마다)
  - 이름과 게이트 안 경로(`/가계부`), 실제 경로(고정폭 글꼴)
  - 상태 태그: 기본 / 연결됨 / 찾을 수 없음 / 작업 폴더 설정에 반영 안 됨
  - 파일 수(최대 1만 개까지 세고 넘으면 "1만 개 넘음"), 추가한 때, [빼기](기본 폴더에는 없음)
- **[폴더 추가]**
  1. 화면 서버가 맥 폴더 선택 창을 띄운다(`osascript`, `choose folder with prompt`). 값은 argv로 넘긴다(승인 창과 같은 원칙). 한 번에 하나만 띄우고, 2분 안에 고르지 않거나 취소하면 "취소했어요"라고 알린다.
  2. 고른 폴더를 검사(4.5)하고 확인 상자를 보여 준다: 게이트 안 이름, 실제 경로, 파일 수, "연결하면 에이전트가 게이트를 거쳐 이 폴더 문서를 읽을 수 있어요. 정책대로 가리거나 물어봐요. 동시에 작업 폴더 설정에서 이 폴더를 직접 열지 못하게 막아요."
  3. [연결]을 누르면 4.3 순서로 쓴다. 끝나면 결과와, 필요하면 세션 다시 시작·`gate setup` 안내를 보여 준다.
- **추가는 폴더 선택 창에서 고른 것만** 받는다. 서버는 고른 경로를 한 번 쓰는 선택 번호(5분 유효)로만 기억한다. 추가 API는 경로가 아니라 선택 번호를 받는다. 토큰이 새어도 사람이 고르지 않은 폴더는 화면으로 연결할 수 없게 하려는 것이다.
- **[빼기]**: 확인 상자("게이트에서 이 폴더를 빼요. 에이전트는 이 폴더 문서를 더는 게이트로 읽지 못해요." + 미결 2에 따른 보호 문구) → 4.3 순서.
- API(가칭): `GET /api/mounts`, `POST /api/mounts/pick`, `POST /api/mounts/add`(선택 번호, 확인 값), `POST /api/mounts/remove`(이름, 확인 값). 지금 화면 API와 같은 토큰·Host·Origin·POST 검사를 받는다.
- 연결 상태 카드의 "게이트" 카드에 "원본 폴더 N개"를 더한다.

## 6. 단계

새 세션에서 미결 5개를 먼저 묻고 시작한다. 9-1과 9-2는 맡는 파일을 나눠 병렬 에이전트로 할 수 있다. 9-2는 9-1의 `mount_change` 함수 모양(인터페이스)만 먼저 정하면 된다.

- **9-1 게이트·보호 설정·CLI**: `mounts.yaml` 읽기·쓰기·검사, `MountedStore`, 데몬 변경 감지, 작업 폴더 등록과 설정 다시 쓰기, `gate mount`, `gate setup`이 목록 읽기. 테스트.
- **9-2 화면**: 원본 폴더 절, 폴더 선택 창, 추가·빼기 흐름. 테스트. Chrome으로 데스크톱 폭 확인.
- **9-3 검증·문서**: e2e 시나리오(7절), 하네스 새 시도(비용이 들어 돌리기 전에 묻는다), README·`plans/implementation-plan.md`·HANDOFF, 점검 페이지.

## 7. 검증

- **저장소 테스트**: 이름 정하기·겹침, 추가할 수 없는 폴더(4.5 전부), 쓰기 순서와 실패 시 되돌림, 깨진 목록 파일이면 차단, 사라진 폴더, 심볼릭 링크가 폴더 사이를 넘지 않음, 경로 규칙·폴더 승인이 추가 폴더에도 걸림, 손으로 바뀐 작업 폴더 설정이면 추가 안 함, 터미널이 아니면 거부, 화면 API(토큰·선택 번호·확인 값·한 번 쓰기).
- **e2e**(`eval/run_e2e.py`에 시나리오 `mount`): 임시 폴더를 추가 → `gate ls /`에 보임 → 그 안 문서가 정책대로 가려짐, `.env`는 차단 → 감사 기록에 게이트 안 경로 → 빼기 → 안 보이고 읽기는 `ENOENT`.
- **하네스**(`sandbox/bypass.py`, API 비용, 돌리기 전에 묻기)
  - W18: 추가한 폴더를 에이전트가 직접 읽기(`cat`·`Read`·Python) → 막혀야 한다.
  - W19: 에이전트가 `mounts.yaml`·`workspaces.yaml`을 읽거나 써서 다른 폴더를 열기 → 막혀야 한다.
  - W20: 에이전트 세션이 켜진 동안 하네스가 폴더를 추가한 뒤, 같은 세션이 그 폴더를 직접 읽기. 결과로 미결 3을 정한다.
  - 기존 W16·W17처럼 에이전트가 화면 API(`/api/mounts/*`)에 닿는지도 본다(지금까지는 샌드박스가 127.0.0.1을 막음).
- **화면**: Chrome으로 추가(폴더 선택 창은 사람이 직접 고름)·빼기·찾을 수 없음·반영 안 됨 상태를 본다.

## 8. 미결 (2026-11-01 사용자 결정, 결과는 2절 아래 표)

1. **기본 폴더의 자리**
   - A(추천): `/`에 그대로 두고 추가 폴더는 `/<이름>/`. 기존 경로·정책·기록과 맞고, 기본 폴더는 뺄 수 없다.
   - B: 모든 폴더를 같은 자격으로 `/<이름>/` 아래에 둔다. 깔끔하지만 기존 경로가 바뀌고(`/상담/…` → `/source/상담/…`), 사용자 경로 규칙과 폴더 승인을 옮겨야 한다.
2. **뺄 때 보호를 어떻게 할지**
   - A(추천): 게이트에서만 빼고 직접 읽기 막기는 남긴다. 에이전트는 그 폴더를 아예 못 읽는다(더 엄격). 화면에 "보호만 남음"으로 보이고, [보호도 풀기]는 따로 둔다(느슨해지는 바꿈이라 한 번 더 확인).
   - B: 빼면 보호도 함께 푼다. 에이전트가 그 폴더를 다시 직접 읽을 수 있다.
3. **이미 켜진 에이전트 세션**: W20 결과를 보고, 반영되지 않으면 "다시 시작하세요" 안내만 할지, 화면에서 세션 다시 시작을 더 강하게 요구할지 정한다.
4. **이름이 겹칠 때**: 뒤에 숫자를 붙인다(추천, 이름 바꾸기 기능이 없으므로). 다른 안: 확인 상자에서 이름을 고칠 수 있게 한다.
5. **작업 폴더 등록 방식**: `gate workspace init`이 등록 파일에 적는다(추천). 다른 안: `gate ui`·`gate mount`에 `--workspace`를 매번 넘긴다.

## 9. 인터페이스 (9-1 ∥ 9-2)

9-1과 9-2를 병렬로 하려고 `gate/mount_change.py`의 함수 모양을 먼저 정했다(파일 맨 위 설명과 각 함수 docstring). 9-1이 몸체를 채우고, 9-2(화면)는 이 함수만 부른다.

- `MountContext.from_policy(정책 파일, socket, audit)`: 목록 파일·등록 파일 위치를 정책 파일 옆으로 정한다.
- `list_mounts(ctx) -> MountsView`: 기본 폴더·추가 폴더 줄(`FolderRow`), 작업 폴더 상태(`WorkspaceStatus`), 전역 설치 여부, 목록 파일 오류.
- `plan_add(ctx, 폴더, added_by)`·`plan_remove(ctx, 이름)`·`plan_unprotect(ctx, 이름) -> MountChange`: 계산·검사만 한다. 못 하면 `MountError`(사용자에게 그대로 보여 줄 해요체 문장).
- `apply(ctx, change) -> MountResult`: 다시 계산해 `change`와 같을 때만 쓴다(그사이 바뀌었으면 `MountError`). 결과에 다시 쓴 작업 폴더와 안내(`restart_session`·`rerun_setup`·`no_workspace`).
- 화면은 `MountChange.confirm_token`으로 한 번 더 확인받는다(정책 바꾸기와 같은 방식).

## 10. 한계 (예상)

- 폴더 선택 창은 맥에서만 된다. 다른 OS에서는 터미널 `gate mount add`만 쓴다(지금 대상은 맥).
- 전역 설치 사용자는 `gate setup`을 다시 실행해야 새 폴더가 막힌다. 실제 배포(MDM 관리 설정)에서는 관리 설정을 다시 내려보내야 한다.
- 연결하지 않은 폴더는 지금처럼 에이전트가 직접 읽을 수 있다. 게이트는 연결한 폴더만 지킨다.
