# Jev 한국어 평가

`samples/`의 합성 한국어 문서로 Jev 판단(라벨 + 확신도)을 평가한다.

```bash
uv run python -m eval.run_eval --client mock            # 요약
uv run python -m eval.run_eval --client mock --details  # 샘플별 결과까지
JEV_BASE_URL=http://127.0.0.1:8000 JEV_MODEL_DIR=/경로/models/laya \
  uv run python -m eval.run_eval --client laya          # 실제 Laya (laya-serve가 떠 있어야 한다)
```

옵션: `--policy`(정책 파일, `gate policy`로 만든 것. 없으면 기본 정책), `--timeout`(Jev 호출 타임아웃, 기본 3초), `--purpose`(질문에 넣을 목적), `--labels`(라벨 파일).

> **Mock 결과는 Jev의 실제 성능(한국어 포함)을 대변하지 않는다.** `MockJevClient`의 keyword 방식은 단순 키워드 규칙이고, 규칙과 샘플을 같은 작업에서 만들었기 때문에 점수에는 의미가 없다. 파이프라인(마스킹 → 질문 → 판단 → 집계)이 도는지 확인하는 용도다. 실제 모델 결과는 아래 [Laya 평가 결과](#laya-평가-결과-phase-3b)에 있다.

## 샘플과 라벨

- 샘플: `samples/<종류>/<경우>_<n>.txt`, 4종류 × 3경우 × 3개 = 36개. 전부 지어낸 내용이다.
  - 종류: `cover_letter`(자기소개서), `consult_chat`(고객 상담 채팅), `medical_note`(진료 메모), `resume`(이력서)
  - 경우: `pii`(개인정보 있음), `quasi`(준식별자만), `none`(없음)
- 라벨: `eval/labels.csv`. 열은 `path`(프로젝트 루트 기준), `expected`, `doc_type`, `case`.

### 라벨 기준

| 경우 | 기대 라벨 | 기준 |
|---|---|---|
| `pii` 개인정보 있음 | `highly_sensitive` | 이름이 있고 연락처·주민등록번호·이메일·카드·계좌 같은 직접 식별자가 함께 있다. 건강·금융·가족 정보가 붙기도 한다 |
| `quasi` 준식별자만 | `sensitive` | 이름과 직접 식별자는 없지만 학교·연도·지역·직업(·"그 지역에서 저 혼자" 같은 단서)을 합치면 특정인을 좁힐 수 있다 |
| `none` 없음 | `safe` | 특정 개인으로 이어지는 정보가 없다. 빈 이력서 양식처럼 "성명", "연락처" 같은 낱말만 있는 문서도 여기에 든다 |

- 라벨은 경우에 따라 기계적으로 정한다(`EXPECTED_BY_CASE`). 테스트가 라벨 파일과 이 규칙이 맞는지 확인한다.
- `pii` 문서에는 정규식이 못 잡는 **이름**이 반드시 들어 있다. 그래서 정규식 마스킹 뒤에도 특정인을 알아볼 수 있다.
- 이름은 홍길동·김철수·이영희·성춘향·이몽룡·심청처럼 흔한 가명을, 번호는 `900101-1234567`, `010-1234-5678`, `4111 1111 1111 1111`, `*@example.com` 같은 예시 값을 쓴다. 학교·회사·병원 이름도 지어냈고, 실존 기관과 겹치는지는 확인하지 않았다. 지역명(시·구)만 실제 이름이다.

## 평가 방식

1. 샘플을 읽어 **정규식 마스킹**한다. 기본은 `gate.detectors.mask`이고, 불러올 수 없거나 마스킹 중 오류가 나면 평가를 멈춘다(마스킹하지 않은 내용은 Jev에 보내지 않는다). 테스트에서는 `evaluate(..., masker=가짜함수)`로 바꿔 끼운다.
2. `RequestContext(요청 프로세스, PID, 가상 경로, 목적)`와 함께 Jev에 묻는다. 가상 경로는 `/<종류>/<해시 8자리>.txt`처럼 **경우를 드러내지 않는 이름**을 쓴다. 파일 이름(`pii_1.txt`)이 답을 알려 주지 않게 하기 위해서다.
3. Jev 호출 시간(마스킹 제외)을 잰다.

### 지표

| 지표 | 정의 |
|---|---|
| 정확도 | 답 = 기대 라벨인 비율. Jev 오류는 틀린 것으로 센다 |
| 안전 여부 정확도 | `safe`인지 아닌지만 맞힌 비율(전체 − 오탐 − 미탐). 예/아니오로 답하는 모델(Laya)은 개인정보와 준식별자를 나누지 못하므로 이 값을 본다. 정책도 두 라벨을 같게 다룬다 |
| 오탐률 | 기대 `safe` 중 `safe`가 아닌 답을 받은 비율. **Jev 오류도 오탐**으로 센다(차단되어 못 보므로) |
| 미탐률 | 기대 `safe` 아님 중 `safe` 답을 받은 비율. 개인정보가 새는 쪽이라 가장 중요하다. Jev 오류는 미탐이 아니다(차단되므로) |
| Jev 오류 | `JevError`(호출 실패, 타임아웃, 응답 형식 오류)와 그 밖의 예외. 따로 센다 |
| 평균 지연 | Jev 호출 시간의 평균과 최대 |

그 밖에 혼동행렬(기대 × 답), 문서 종류별·경우별 표, 정규식 탐지 건수(경우별)를 보여 준다.

### 게이트 결과

데몬과 같은 정책 엔진(`gate/policy.py`)으로 낸 결과다(Phase 4에서 바꿨다. 그 전에는 임계값 하나로 미리 보기만 했다). 번호 종류별 동작과 Jev 답을 합쳐 가장 엄격한 것을 고른다. 키워드 Mock으로 데몬 결과와 이 결과가 샘플 36개 모두에서 같은지 `tests/test_integration.py`가 확인한다.

- 기본 정책: `safe`이고 확신도 ≥ 0.95 → 허용(번호가 있으면 가림), 민감하고 확신도 ≥ 0.95 → 차단, 그 사이 → 사람 승인
- 번호·비밀값 종류별 동작(`numbers.<종류>.action`)이 `deny`나 `ask_human`이면 그쪽이 이긴다
- Jev 오류 → 차단 (실패하면 차단이 기본)
- 사람 승인은 묻지 않고 "사람 승인"으로 센다. 샘플은 `.txt`라 경로 규칙은 적용되지 않는다

## Laya 평가 결과 (Phase 3b)

팀원이 파인튜닝한 Laya 체크포인트(laya-multilingual 기반, 예/아니오 질문 하나)를 로컬 `laya-serve`로 띄워 평가했다(2026-10-31, 맥 M5 mps, 기본 정책). 연결 방법은 저장소 README "판단 모델 연결 (Laya)"에 있다. 그림과 샘플별 표, 팀원 모델 분석은 [평가 보고서](https://claude.ai/artifact/4WaSWgekRir4frkRCq1a2L)에 있다.

| 지표 | 값 |
|---|---|
| 미탐률 | 0/24 (0%) |
| 오탐률 | 6/12 (50%) |
| 안전 여부 정확도 | 30/36 (83%) |
| 정확도 (3종 라벨) | 18/36. 예/아니오라 `highly_sensitive`를 내지 않는다 |
| Jev 오류 | 0 |
| 평균 지연 | 52ms (최대 169ms) |

- 게이트 결과: 민감 24개는 모두 차단. 안전 12개는 허용 1, 사람 승인 10, 차단 1.
- 문서 종류별 오탐: 상담채팅 0/3, 자기소개서 2/3, 진료메모 2/3, 이력서 2/3. 팀원 학습 분야(상담) 밖의 문서 형식에서 개인정보가 없어도 민감으로 본다.
- 임계값을 옮겨서는 못 고친다. 안전 문서 최고 p(진료메모 none_3, 0.958)가 준식별자 문서 최저 p(이력서 quasi_1, 0.951)보다 높다.
- 가린 입력과 원문 입력은 판단·게이트 결과가 36개 모두 같았다(p 차이 최대 0.008).
- 450자가 넘는 샘플 8개는 조각으로 나눠 묻는다. 문서 전체를 한 번에 물으면 오탐이 7/12였다(이력서 none_2가 0.555 → 0.15).
- 명세 Phase 3 완료 조건에 따라 대안을 제안하고 멈췄다. 사용자 결정: 팀원이 추가 학습 중이므로 지금 모델로 연결을 끝내고, 재학습한 체크포인트가 오면 폴더를 바꿔 같은 36개로 다시 평가한다.

**체크포인트를 바꿀 때**: 새 폴더로 laya-serve를 다시 띄우고 위 명령을 돌린다. 질문이 바뀌었으면 새 `questions.json`이 폴더에 함께 있어야 한다. 이 샘플 36개는 학습에 쓰지 않는다(평가 전용).

## 알려진 한계

- 샘플 36개는 통계적으로 작다. 한 건이 정확도 약 3%p를 움직인다. 안전 샘플은 12개라 오탐률은 한 건에 약 8%p 움직인다.
- 샘플과 라벨을 한 사람(에이전트)이 썼다. 라벨이 애매한 문서가 있다.
  - 준식별자 + 건강 정보(진료 메모 `quasi`)는 `highly_sensitive`로 볼 수도 있지만 경우 규칙대로 `sensitive`로 두었다.
  - `pii` 문서는 마스킹 뒤 이름만 남으므로 판단에 따라 `sensitive`가 나올 수 있다. 정책상 둘 다 높은 확신도면 차단이라 결과는 같다.
